# Full Qwen MoE streaming on S25 Adreno

One successful short run of the complete 40-layer text model in Colibri,
on SM-S938W / SM8750 (S25 Ultra), Android 16, native Termux, Adreno 830.
Engine revision: `02d693d6409eb305a42d364db19c3f2fc362d61a`.
The process exited 0 and issued 12,102 Vulkan dense dispatches.

## Model and placement

Source: `Huihui-Qwen3.6-35B-A3B-Claude-4.7-Opus-abliterated-ggml-model-Q8_0.gguf`.
Source SHA-256:
`40a6af1867dad47ca06bc5b1d0979dcbf918937ebd1d34e6e856f90dec4bcbb1`.
The source name is artifact provenance, not an independent validation of its
fine-tuning claims. This is the existing Qwen3.6 artifact, not Qwen3.8.

The experimental GGUF converter produced 45 files totaling 23,031,847,456
bytes (21.45 GiB), excluding the manifest. Every file's size and SHA-256 were
verified on the device immediately before loading. Experts were requantized
from Q8_0 to signed INT4, group size 64. Dense matrices were stored FP16 and
quantized to per-row INT8 during loading. MTP and vision are excluded.
The conversion used `--v-head-order tiled`.

Adreno held 291 dense matrices, 1,848.5 MiB of logical quantized weights.
The GPU performs dense GEMVs; CPU handles routed expert kernels, attention
state, DeltaNet recurrence, norms and routing selection. Expert weights stream
from storage through an eight-slot cache per layer. Embedding rows also stream.
This is GPU-assisted Colibri; it is not a Hexagon or GPU-expert benchmark.

## Results

Prompt: 32 tokens. Requested and generated: 32 tokens. Greedy decoding.
The CPU expert kernel used its default INT8 activation mode; dense Vulkan
activations remained FP32.

| Measurement | Result |
| --- | ---: |
| Decode step, 31 steps after the first output token | 2,082.1 ms/token |
| Decode throughput (`1000 / 2082.1`) | **0.4803 tokens/s** |
| Prompt processing plus all 32 generated tokens | 128.4 s |
| Overall generation rate including prompt processing | 0.25 tokens/s |
| Time to first token, excluding model loading | 63.88 s |
| Resident weight loading | 16.2 s |
| Reported RSS after load | 1.98 GB |
| Reported peak RSS | 2.46 GB |
| Expert cache hit rate, prefill and decode combined | 27.7% |

Decode breakdown: MoE 1,930.95 ms/token (92.7% of step time), including
shared and router work. Expert fetch accounts for 1,163.59 ms/token and expert
compute 731.84 ms/token. Fetch includes cache lookup, loading and preparation;
it is not a measurement of raw UFS latency. DeltaNet takes 95.08 ms/token,
attention 22.63 and the output head 31.73.

The phone was unplugged, 74% battery before and 73% after. Android thermal
status remained 0 at the sampled checkpoints; skin temperature was 34.5 C
before checksum verification and 37.0 C after the run. Available system memory
was 5,795 MiB at inference preflight. Existing Android zram was in use; this is
not an isolated memory benchmark. Process RSS does not account for all GPU or
system memory. No thermal or memory protections were disabled.

Generated text (the fixed token limit ends mid-answer):

> Mixture-of-Experts (MoE) models have many more parameters than dense models, but at any given moment, only a small subset of experts are activated

This is one short functional/performance measurement, not sustained thermal
throughput, a cold-storage test, a CPU-versus-GPU speedup comparison, or a
perplexity qualification of the lossy conversion. Checksumming preceded the
run and affected page-cache state. The result establishes full-model execution
with bounded residency; it does not establish original-Q8 quality equivalence.

## Reproduce

Build with `make -C c qwen36 VK=1 CC=clang`. From `c/`, with the converted
container and matching tokenizer:

```sh
unset SERVE PPL DUMP COLI_KEEP_F32
COLI_VULKAN=1 COLI_CUDA=0 COLI_DENSE_I8=1 \
COLI_DENSE_BITS=8 COLI_DENSE_IDOT=0 \
QWEN_VK_DENSE_MB=2048 QWEN_EMBED_STREAM=1 Q36_MAXT=1024 \
OMP_NUM_THREADS=4 OMP_WAIT_POLICY=PASSIVE COLI_NO_OMP_TUNE=1 \
PILOT=0 HOT=0 N_NEW=32 COLI_TIMERS=1 \
SNAP=/path/to/container TOK=/path/to/container/tokenizer.json \
COLI_VK_SHADERS="$PWD/shaders/qmatmul.spv" \
./qwen36 8 4 prompt.txt
```

Exact prompt file, including a final newline:

```text
<|im_start|>user
Briefly explain why streaming only the active experts lets a large MoE model run on a phone.<|im_end|>
<|im_start|>assistant
<think>

</think>

```

The tested binary SHA-256 was
`280bd9be9d48d0169f1b9ffb62b03030a4c46bc723855a086a30c7626c7c16eb`.
The adjacent [raw log](qwen36-s25-adreno-2026-10-09-raw.txt) changes only the
device-local model directory to `/path/to/container`.
