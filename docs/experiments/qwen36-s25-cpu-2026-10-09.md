# Full Qwen MoE streaming on S25 CPU only

The full 40-layer Huihui Qwen3.6-35B-A3B text model completed a CPU-only Colibri
run on S25 Ultra (SM-S938W / SM8750), Android 16, native Termux. Exit code 0;
32 prompt tokens and 32 generated tokens. This uses the same converted
21.45 GiB container and exact prompt as the
[Adreno baseline](qwen36-s25-adreno-2026-10-09.md).
All 45 model file sizes and SHA-256 values passed verification before loading.

`COLI_VULKAN=0`, `COLI_HEXAGON=0`, and `COLI_CUDA=0` explicitly disabled
accelerators. The log records **zero Vulkan dispatches** and no QNN graph
initialization or execution. The tested binary contains optional accelerator
support, but all inference computation in this run occurred on CPU.

## Three-path comparison

| Measurement | CPU only | Adreno dense + CPU experts | Adreno dense + Hexagon experts |
| --- | ---: | ---: | ---: |
| Decode step, 31 steps | 2,714.2 ms/token | 2,082.1 ms/token | 2,659.4 ms/token |
| Decode throughput | **0.3684 tokens/s** | **0.4803 tokens/s** | **0.3760 tokens/s** |
| Prompt + 32 output tokens | 165.3 s | 128.4 s | 171.8 s |
| Overall rate including prompt | 0.19 tokens/s | 0.25 tokens/s | 0.19 tokens/s |
| TTFT, excluding model load | 81.11 s | 63.88 s | 89.38 s |
| Resident weight loading | 15.4 s | 16.2 s | 17.2 s |
| Reported peak RSS | 2.51 GB | 2.46 GB | 2.45 GB |
| Whole-run expert cache hit rate | 27.6% | 27.7% | 28.0% |

Adreno dense acceleration delivered 30.4% higher decode throughput than
CPU-only in these individual runs. The Hexagon hybrid was only 2.1% faster
than CPU-only, too small a difference to treat as a robust advantage from one
short run. See the [Hexagon report](qwen36-s25-hexagon-2026-10-09.md) for its
FP16 staging overhead, sampled numerical checks and light thermal throttling.

CPU-only decode breakdown:

| Phase | ms/token |
| --- | ---: |
| DeltaNet | 371.36 |
| Attention | 98.78 |
| MoE total, including shared and router | 2,064.08 |
| Output head | 177.72 |
| Expert fetch (subset of MoE) | 1,271.31 |
| Expert compute (subset of MoE) | 731.68 |

The CPU and Adreno runs both use dense INT8 weights with FP32 activations,
INT4 gs64 experts with the CPU kernel's INT8 activation mode, four threads,
eight cached experts per layer, streamed embeddings, and a 1,024-token context
limit. The Hexagon expert graph uses FP16 IO/computation. Generated text and
therefore routing differ between the runs. These are neither bit-equivalence
nor equal-quality claims, and do not establish an intrinsic hardware speed ratio.
Expert fetch includes cache/loading/preparation, not just UFS latency.

## Conditions and output

The phone was unplugged, 69% battery before and 68% afterward. Android thermal
status remained 0 at sampled checkpoints; skin temperature was 33.5 C before
checksum verification and 37.4 C immediately after generation. Available
memory at inference preflight was 5,627 MiB. Existing Android zram was in use.
RSS does not capture all system/accelerator allocations across these runs.
Checksumming affects page-cache state, so these are not cold-storage tests.
No protections were disabled. This is one short run, not a thread-count tuning
sweep or sustained thermal measurement.

## Reproduce

Use the exact prompt file from the Adreno report. From `c/`:

```sh
unset SERVE PPL DUMP COLI_KEEP_F32
COLI_VULKAN=0 COLI_HEXAGON=0 COLI_CUDA=0 QWEN_EXPERT_ACT=i8 \
COLI_DENSE_I8=1 COLI_DENSE_BITS=8 COLI_DENSE_IDOT=0 \
QWEN_EMBED_STREAM=1 Q36_MAXT=1024 \
OMP_NUM_THREADS=4 OMP_WAIT_POLICY=PASSIVE COLI_NO_OMP_TUNE=1 \
PILOT=0 HOT=0 N_NEW=32 COLI_TIMERS=1 \
SNAP=/path/to/container TOK=/path/to/container/tokenizer.json \
./qwen36 8 4 prompt.txt
```
